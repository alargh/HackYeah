# Edit a Specification

Read the applicable repository instructions, `.ai/WORKFLOW.md` when present, the complete named specification, and evidence relevant to the requested change.

- Edit the specification and directly relevant decision or research records.
- Preserve the original goal and completed execution evidence unless the user changes the goal or new evidence warrants a correction.
  Record meaningful corrections in the affected task's `Deviations`.
- Recalculate task boundaries, dependencies, allowed files, validation, and success criteria after scope changes.
- Identify completed tasks that need follow-up validation or rework.
  Do not leave an invalidated result marked complete.
- Record assumptions and unresolved decisions explicitly.
  Use implementation, reproducible outputs, or authoritative sources for factual claims as appropriate.
- Keep specification text in English unless the user requests another language.

Update the `Updated` date and record material changes to already approved scope.
Preserve approval for unaffected work; record new scope as pending authorization unless the user's request already authorizes it.
Do not implement product changes when the request is only to edit the specification.

Finish with the meaningful changes, remaining decisions, and specification path.
